# Agent Atlas

Learn how AI agents work, communicate and are orchestrated. Watch real recorded runs replayed step by step, and read short articles on each concept.

Agent Atlas is an educational project. It is not meant for real work.

Site: https://agentatlas.academy

Source: https://github.com/cimenta/agent-atlas-academy

## Run it

Requires Node.js 20 or newer. There are no dependencies to install.

```bash
npm start
```

This builds the generated files and serves `public/` at http://localhost:8080.

```bash
npm test
```

```bash
npm run build
```

Writes `public/version.json` and the article indexes (generated, not committed).

## Live runs

Visitors can run their own experiment with their own API key: describe a task, pick a pattern (sequential, parallel, supervisor, debate, evaluator loop, handoff, router, voting, map-reduce, plan-and-execute), pick one or more providers (Anthropic, Gemini free or paid, and Groq, OpenRouter and Cloudflare Workers AI, which have free tiers), build a diagram of agents and watch it run in the player. A Default model sets the model of every agent and one agent can have its own, so a run may mix providers.

- **Try it without a key:** `npm run build && node scripts/serve.js --mock` answers `/api/run` with fake agents. Any key text of 20 or more characters works and nothing is sent to Anthropic. The flag is refused when `VERCEL` is set.
- **Endpoint:** `POST /api/run` (`api/run.js`, logic in `lib/run-handler.js`) takes `{ design, task, limits, language, keys, timeoutSec, outputTokens, retries, retryDelaySec, freeTier, repeatStop, handoffChars, resume }` and streams the run as server-sent events. `keys` holds one key for each key slot the agents use (the slot ids are in `public/js/engine/providers.js`, for example `anthropic`, `google-free`, `google`, `groq`, `openrouter`, `cloudflare`; an older single `apiKey` still works). Keys are used only for the calls to the providers and are never logged or stored. `timeoutSec` (30 to 120, default 60) is how long one request to a model waits. `resume` holds the answers of agents that finished in an earlier try, which is how Retry carries a failed run on. There is a per-address limit of 10 runs an hour (`RUNS_PER_HOUR` changes it) and the function may run for five minutes.
- **Retry:** a failed agent shows a red Retry button with an arrow that offers another model for that agent. The run carries on from it in the same saved record; the agents that finished are not called again (`resume`). The Retry menu has a Use current limits from Settings checkbox (`public/js/replay/limits-choice.js`, pure parts in `limits-compare.js`: `compareLimits`, `predictStop`, `withCurrentLimits`, `labHref`); checked (the default), the record is resumed with `clampLimits(settings.limits)` instead of its own `limits`, and when the recorded steps already pass the new limits (or leave no room for the retried agent) the expanded details offer a link to `#/learn/lab?run=&steps=&tokens=&repeat=`, which the lab reads (`parseRoute` returns the query as `params`; a run of the visitor's own is added to the run list). Create reads its limits from the settings store each time it opens unless the visitor edited them (`draft.limitsEdited`); `openInCreate` resets `draft.limits` and `limitsEdited`, so Use in Create always starts from the limits of Settings. The result message shows the cost of that try and of the whole run, and an agent on a free Gemini key counts as free.
- **Submit to library:** the run menu of a visitor's own finished run has Submit to library. It saves the run as the same file Export run makes and opens a `mailto:` link to submit-run@agentatlas.academy with a message that asks to attach it (`public/js/submit-run.js`). The site sends nothing and stores nothing; the owner reviews what arrives and adds good runs to `public/runs/` and `index.json`.
- **Library cards:** an icon (check, square, cross) shows how a run ended and colored chips name its providers; the colors are chosen in Settings.
- **Shared engine:** the pattern rules, runners, limits and cost estimate live in `public/js/engine/` and are used by both the browser and the function, so the editor and the server always agree.
- **Limits:** a task is at most 1000 characters; a design has at most 8 agents; defaults are 20 steps, 40000 tokens and 3 web searches, and the hard maxima are 60, 150000 and 10. `limits.maxCostUsd` is an optional cost cap (0.10 to 5.00 US dollars, absent means off): the run stops with the reason `cost` when the estimated cost, by the catalog prices and counting only agents not on a free key, passes it. A run also stops after 270 seconds. One reply of an agent has at most 4000 tokens by default; the visitor can lower it to 1000 (`outputTokens`, clamped by the server).
- **Harness:** everything around the model (the limits above, the request timeout, the retries and the key handling) is described for the visitor on Settings, Harness: a Fixed harness page (the rules that cannot be changed) and the adjustable pages Limits, Retries, Cost and Guards, which share one Save and one Reset. Every setting has a ? button (`helpIcon` in `public/js/help-popup.js`) that opens a popup with one section of the Help text: Help is the only place the words are written. A Help topic has small sections `### Title {#id}` (the harness ones are `harness-steps`, `harness-cost` and so on) and an optional line `{related: id, id}`; `public/js/help-topics.js` splits them, the popup shows the section with chips for the related ones and a link to `#/help/<id>`, which opens the topic at that section. A test fails when a ? points at a section that is missing in English or in Czech. The same ? buttons are on the Settings tabs and the Create steps (`help("settings-keys", name)` and so on); Settings, General has a Hide the ? help buttons option (`helpButtons` in the settings store, applied as `data-help` on the page and hidden by one rule in `styles.css`). The player has a ? at the speed control and at each of its three tabs, a warning in a replay has a ? chosen by `warningHelp` in `public/js/help-ids.js` (from the `limit`, `handoff`, `retry` or `truncated` field of the event), and the Result page has one at How it ended, Estimated cost, Tokens per agent and Limits. Settings, Harness, Tools has the master switch for web search (`webSearch` in the settings store, sent with a run and read by `lib/run-handler.js` as `allowSearch`; `runDesign` then gives the budget no searches, so no agent is given the tool, and adds a `warning` with `webSearchOff`). In Create each agent has its own search switch under Tools. Every agent with `search` on gets `WEB_DATA_RULE` (`public/js/engine/prompts.js`) in its system prompt, which says text from the web is data and not instructions, the Harness fixed page lists it, and the replay labels search results as untrusted web content. It is a reminder to the model, not a guarantee. Settings, Harness, Fallback model has the Fallback model setting (`fallback`: `off`, `suggest`, the default, or `auto`; `clampFallback` and `fallbackModelFor` in `public/js/engine/catalog.js`). It acts when an agent is out of tries: with `auto`, `createAgent` switches once to another model of the same provider (Fast to Balanced, Balanced to Fast, Strong to Balanced; never a model a free Gemini key cannot use), emits a `warning` with `fallback`, and the cost follows the model that answered; with `suggest`, `retryChoices` marks that model as `suggested` in the Retry menu. Human approval: a node can carry `approve: true` (validated in `patterns.js`, kept by the editor, shown as the Approval group under the settings of an agent). `createAgent` gets `askFirst` for such a node unless the run says it is `approved`; on its first live activation it emits an `approval` event (the input it would receive, cut at `APPROVAL_INPUT_MAX`) and throws `ApprovalPause` (`public/js/engine/approval.js`), which `runDesign` turns into the outcome `waiting_approval` with no error. No connection is held open: Approve (`approvalPanel` in `public/js/approval-panel.js`, in Create after a run and in Play for a saved run) carries the run on like Retry, with the saved answers as `resume` and the approved agents as `approved` (an `approved` event is added to the record, and `pendingApprovals` and `approvedAgents` read the events). Stop here rewrites the `done` outcome to `stopped_user`. In a parallel run the agents that were still working are lost and run again after Approve. The Harness lab (`#/learn/lab`, `public/js/harness-lab.js`) plays a recorded run of the library against limits the visitor sets, without a provider call. `public/js/harness-lab-model.js` is pure: `labSteps` turns the `round` events of a run into steps (tokens, end time, the answer of an agent on its last call), `labRanges` gives the slider ranges and the sliders start at the limits of the settings store (kept inside the range of each slider; the time always starts wide open), and `simulate` applies the limits the way the budget of the engine does (a step that would pass the step limit is not taken; a step that passes the token or time limit is the last one; the same answer of one agent N times in a row stops the run). It does not model web searches, the cost cap or limits of single agents. The tabs of Settings are API keys, Harness, Player controls, General (tooltips and help buttons), Data, Shortcuts and Security. The Limits page has three profiles (Careful, Balanced, Generous, and Custom when the sliders match none; `PROFILES` and `matchProfile` in `public/js/engine/catalog.js`) that set the five limits at once (steps, tokens per run, web searches, tokens of one reply and the request timeout), a Retries section (`retries` 0 to 3, default 1, and `retryDelaySec` 1 to 10, default 1.5; every try costs a step, only errors with `retryable` set are retried) and an optional Cost cap (`limits.maxCostUsd`, see Limits). The browser keeps all of it in the settings store and sends `outputTokens`, `retries` and `retryDelaySec` with a run; the server clips each one with the `clamp*` helpers of the catalog. The cost of a call is `usageCostUsd` in `public/js/engine/cost.js`; the budget adds it up after each answer and stops the run with the reason `cost`. Two guards run inside the engine. Loop detection (`repeatStop`: 0 is off, 2 to 4, default 3) is in `createAgent`: when one agent gives the same answer (ignoring capitals and spacing) that many times in a row the run stops with the reason `repeat` and a warning that names the agent. The size of a handoff (`handoffChars`: 0 is off, 2000 to 20000) is `createPassOn` in `public/js/engine/handoff.js`, handed to every runner as `passOn`: a longer text is cut before it goes into the input of the next agent, with a line that says so and a `warning` event carrying `handoff` once; the events of the replay keep the whole answer. Create shows a warning under the estimate when `limitWarning` in `public/js/engine/estimate.js` says the design needs more turns or tokens than the limits give. The fixed values are read from the same constants the code uses (`public/js/engine/harness.js`). When a limit stops a run the engine adds a `warning` event with a `limit` field right before `done`, so the replay shows which limit it was. An agent can also carry limits of its own: `node.limits` (`maxSteps`, `maxTokens`, `maxOutputTokens`, `maxSearches`, each optional, ranges in `public/js/engine/agent-limits.js`) and `node.onLimit` (`stop`, the default, or `pass`). `createBudget(...).forAgent(limits)` gives the agent a budget that charges the run as well; the lower of the two limits wins. With `stop` the run ends with the reason `agent_steps`, `agent_tokens` or `agent_searches` and a warning that names the agent; with `pass` the agent hands on what it wrote, with a warning carrying the same `limit`, and the run goes on. The Statistics tab shows a Limits table built from these events.
- **Memory management:** three optional parts, all off by default, so a run without them works as before. The Context tab of the replay (`public/js/replay/context-model.js`, `contextOf` and `contextPerCall`) shows for each model call of an agent the exact input tokens and what the call was made of (instructions, the task, what other agents passed on, its own earlier messages, as shares of characters); `runMetrics(run)` gives the figures of one run (steps, tokens, cost, time, largest context, notes, saved characters, outcome) and the Statistics tab shows the largest context and the context per call. The shared notebook is `design.memory.notebook` plus a choice per agent, `node.notebook` (`none`, `read`, `write` or `both`; an agent whose reply is read as a decision can only read): an agent that may write ends its answer with a note, `public/js/engine/notebook.js` takes it out of the text that goes on and adds it to the notebook (a note is cut at 600 characters, an agent reads the last 6000), and an agent that may read gets the notes so far at the end of its input. Nothing is kept between runs. Condensing is `node.condense`: before such an agent starts, `public/js/engine/condense.js` makes one extra call to the fast model of the same provider that shortens what earlier agents passed on to at most 150 words (the task is never shortened and a text of 1500 characters or less is passed on as it is). The call counts as a step and its tokens count against the limits and the cost cap; the estimate adds one step per condensing agent and the run records a `condense` event with the sizes, the summary and the full text. The replay shows the notebook as a panel (`replay/notebook-model.js`) and condensing as a box with marks on the agents (`replay/condense-model.js`).
- **Comparing runs:** in the library of Play a run has a tick box (`data-ui="compare-select"`); two to four ticked runs open `#/play/compare?runs=a,b,c` (`parseRoute` in `public/js/router.js` keeps up to four unique ids). The first ticked run is the base. `public/js/compare-page.js` loads the runs (a run that cannot be opened is listed and left out) and draws a Table view and a Side by side view. Everything is read from the recordings, so old runs compare too: `public/js/compare-model.js` has `differences(runs)` (only the rows whose values are not all equal: pattern, rounds, task, language, provider, notebook, the agents that exist in only some runs, and for each agent in all runs its model, search, notebook choice, condensing and limits, then the run limits), `metricsRows(runs)` (time, cost, tokens, steps, largest context, notes, saved characters and outcome with the difference from the base; the percentage is left out when the base is 0 or unknown) and `headline(runs)`. `public/js/compare-view.js` draws the table: what changed, what it changed (neutral arrows, never colours for good or bad), the results next to each other and the student's own verdict, because quality cannot be measured by the program. The verdict (`public/js/compare-verdict.js`, `aa.compareVerdicts` in the browser storage, keyed by the sorted run ids, at most 50 entries, a note of at most 200 characters) is hidden when the tasks differ. The Side by side view (`public/js/compare-side.js`) plays up to three runs on one clock (`public/js/compare-sync.js`, `createCompareClock`): By time every run is at the same moment and a run that has ended keeps its last picture; By step every run is at the same step. Each column shows its agents, the notebook and condensing marks, the last text and the running time, cost and tokens. The clock takes `{ setTimeout, clearTimeout }` so the tests use a fake one. Help has the section `compare-runs` and Learn has How to compare runs.
- **Storage in the browser:** `aa.compareVerdicts` (the verdict and note of each comparison), `aa.lang` (language), `aa.settings` (harness settings: limits, reply size and request timeout; provider colors, player layout, shortcuts), `aa.vault` (the API keys, only if the visitor chose to remember them, encrypted with one password), and the IndexedDB database `aa` with a `runs` store (every run). Settings has a backup export and import.
- **More providers:** Groq, OpenRouter and Cloudflare Workers AI have their own modules in `public/js/engine/` (`groq.js`, `openrouter.js`, `cloudflare.js`, sharing `openai-compat.js`). The engine builds every request in the Anthropic shape and each module translates it, so the agents and the replay do not know the difference. Settings, API keys, Check models (`POST /api/models`, `lib/models-handler.js`, `public/js/model-check-client.js`) asks a provider which models a key may use and shows what is missing. Free tiers have limits: `engine/limits.js` and `engine/pacing.js` pace the calls, and a long wait or a day limit stops the run so it can be carried on later. Help has the sections `groq`, `openrouter` and `cloudflare`.
- **API calls tab:** the replay lists every call to the provider for the chosen agent (`engine/api-log.js`): the address, headers and body sent and what came back, with the key and anything that identifies the account hidden. It is saved in the run as `apiCalls`; a very large log may be dropped when the run is stored (`apiCallsDropped`). Help section `replay-api`.
- **Answer format and guardrails:** an agent whose reply has a fixed shape can be made to give it (`engine/format.js`, `engine/schema.js`; Help section `harness-format`), and `engine/guardrails.js` adds optional checks described in Help section `guardrails`.
- **Library:** the first tab of Play (`public/js/library-page.js`, `library-model.js`, `library-detail.js`) lists the example runs and the visitor's own, with search and a detail pane (`runs/<id>.detail.<lang>.json` for example runs, listed under `detail` in `runs/index.json`). A run can be loaded, ticked for comparison, used in Create, renamed or removed. The keys are in `public/js/shortcuts.js` (`PAGE_KEYS`, group Library in Settings, Shortcuts) and `library-keys.js`.
- **Import and export of runs:** Export ticked, Export all my runs and Import (`public/js/run-bundle.js`, `library-import.js`) use one file format, `{ format: "agent-atlas-run-bundle", version: 1, runs: [...] }`; a single run file also imports. `planImport` skips a run that is already there, gives a new id to one whose id is taken or is not a safe slug, and refuses an invalid one; a summary is shown after the import. Help sections `library-bundle` and `library-keys`.
- **Articles:** Learn has short articles in `public/content/articles/<lang>/<slug>.md` (front matter: title, section, order, summary, related); `npm run build` writes the index of each language. Messages, system and tools explains what a call to a model really contains.
- **Before it goes public:** model prices and the web-search tool type in `public/js/engine/catalog.js` and `tools.js` must be checked against Anthropic's current documentation.

## Releases

The version lives in `package.json` and is shown in the footer. The project owner uses two scripts. `test.bat` commits the changes on main and raises the dev number (for example 0.2.1-dev.3, shown in the site header) and pushes to the `dev` branch, where Vercel builds a preview to test. `release.bat`: without an argument it shows the current version; `release.bat patch|minor|major` commits everything with a message, bumps the version, tags it, pushes and creates a GitHub release. A release is refused while any owner placeholder marker is left in the legal texts, `README.md` or `SECURITY.md` (`npm run check:release`).

## Contributing a language

1. Add the language code to `SUPPORTED_LANGUAGES` in `public/js/i18n.js` (and update the list asserted in `tests/i18n.test.js`).
2. Copy `public/locales/en.json` to `public/locales/<code>.json` and translate every value. Add a `lang.<code>` key (the language's own name) to every locale file.
3. Add `public/content/articles/<code>/` and `public/content/pages/<code>/` files with the same names as the English ones. Any article or page you leave out falls back to English, with a notice.
4. Run `npm test`. The locale tests fail until every key exists and every placeholder such as `{speed}` is kept.

Contributions are reviewed in pull requests. By contributing text you agree it is licensed under CC BY 4.0.
