# Changelog

All notable changes are listed here. The format follows Keep a Changelog and the project uses semantic versioning.

## [Unreleased]

### Fixed

- Create: loading a definition from a file while the Create page is open ran the next run with the built-in limits instead of the limits of Settings, so a cost cap was ignored. The limits are now read from Settings when the file is loaded.

### Changed

- Library, wave 2: rel-cap-low and rel-cap-ok are recorded (five Strong agents and a combiner with a cost cap of 0.10 USD, which stops the run, and of 0.50 USD, which lets it finish), with details and explanations in English and Czech. The unused definition wave2-save-provider-anthropic is removed.
- Home: more compact. The heading is See and learn how AI agents work together, the Task line above the player is gone, and the Start here card is one blue line; the whole card is clickable (and opens with Enter or Space), More goals stays a link.

### Added

- Library, wave 2 started: 17 run definitions for the goals Cost and speed and Reliability (demo-definitions/wave2-*.json), and sixteen recorded runs on Anthropic with details and explanations in English and Czech: save-models-strong and save-models-mixed, save-serial and save-parallel, save-search-off and save-search-on, rel-format-free and rel-format-fields, rel-eval-vague and rel-eval-good, rel-guard-leak and rel-guard-stop (the guardrail stops the run on purpose), rel-approve-yes and rel-approve-no, rel-guard-repair and more-self-critique. The path-coverage check skips the goals save, reliable and wrong until they are complete.
- Library: supervisor-complex (Anthropic) is recorded, with details and explanations in English and Czech.
- Library, cog menu: Delete ticked and Delete all mine remove your own runs after one confirmation that says how many; the library's own runs are never deleted.
- Re-play, run menu: Mark as done (and Mark as not done) for a library run that is on the recommended path; it marks the run in every goal it belongs to.
- Library, cog menu: Not done only (and Show all runs) leaves the runs marked as done out of the list.
- Library: ten more recorded example runs (debate-simple, router-simple, evaluator-simple, sequential-complex, mapreduce-simple, mapreduce-complex, planexec-simple, planexec-complex, handoff-simple, handoff-complex) with details and explanations in English and Czech, on Gemini, Groq, Cloudflare and Anthropic.
- Library, detail: the tags of the run are shown under the facts, each word in the colour of its group.
- Library, recommended path: a new tab on the right side with four goals (Patterns of teamwork, Cost and speed, Reliability, What goes wrong), each with steps in three levels (beginner, advanced, expert). A step has a number, Open and Done; done steps are kept on this device, and a Continue box points to the next step. Tags filter the path and the list together, and a switch limits the list on the left to the chosen goal.
- Library, right side: three tabs, Recommended path (shown on the first visit, with no run chosen), Tags and Detail. The arrow keys move between them, and the letter T opens Tags.
- Library, run card: the result is the colour of the whole card (green finished, amber stopped, red failed) instead of an icon, the level is three dots at the bottom right, the step number sits at the top right, and a chip says whether a run is one of a before and after pair or bad on purpose.
- Home: a Start here card leads to the recommended path, or continues with the next step (Start, Continue, or a word that the goal is done).
- Library data: the runs in runs/index.json may carry level, kind (pair or bad), twin, paths (goal and step) and teaches (EN and CS); tests check that every goal has at least two runs on each level and that twins name each other.
- Run definitions may carry a library section (level, kind, twin, path, tags and a one-line teaches in English and Czech), so a shared definition holds everything the Library needs. Create ignores it; scripts/add-library-run.js reads it with --definition.
- scripts/add-library-run.js adds one exported run to the library: it checks the run (size, script tags, goal, level, twin) and writes the run file and its index entry.
- Twenty run definitions for wave 1 of the Library revamp (ten patterns, a simple and a complex run each), with About texts in English and Czech, and docs/library-recording.md, the checklist for recording them with a paid Anthropic key.

It counts only calls made in this tab and starts again at 00:00 UTC.

A run carried on from an earlier try continues from its time.

It also opens when a box is focused with the keyboard.

Each library run has tags (what it is about and what the student can learn); a tag is bigger the more runs carry it, the number is next to it, the most frequent one is in the middle and related tags share a colour. Clicking tags narrows the list to the runs that have all of them; Clear filters sits next to Compare. The Tags switch at the right end of the tab row, or the T key, swaps the cloud and the detail of the chosen run.

The little arrow button inside the agent is gone.

Loading it in Create puts that text on the run it makes, so the run can be exported and imported into the Library with its description. Six test definitions for Groq, OpenRouter and Cloudflare (a simple run and a run that hits the limit for each) are in demo-definitions.
- Article Messages, system and tools (English and Czech): what a call to a model contains, why a conversation is a list of messages that is sent again every call, how system differs from messages, and how tools make a message round trip. README now covers the newer providers, the API calls tab, the Library and import and export.
- Library: Play has a new first tab, Library, which is now the page you land on. The list has two tabs, Your runs and Library, with the card of today (title and how the run ended, date, provider chips, pattern) and a tick box at the right; a click anywhere on a card shows its detail: what the run is about, how it works, what the student learns, what to watch for in the replay, the settings of each agent and related articles (for your own runs also your description). Load opens the run in Re-play, which now shows only the player and a link back to the Library; Use in Create, Export, Compare with, and for your own runs Send, Delete and Edit description are buttons in the detail. The search box stays in the header and is the same on Library, Re-play and Result; on the Library it also searches the detail texts. The cog menu and the show or hide button are gone. The detail files of the example runs are temporary and will be replaced with the new scenarios.
- Import and export of several runs: Export ticked and Export all my runs save one JSON file (a bundle); a file with one run is a bundle of one. Import takes several files at once and shows a summary above the list: added, skipped (you already have it), saved as a copy (the same id with other content) or refused with the reason. An import never replaces a run, and importing the same file twice changes nothing. If the browser is full, the runs saved before stay and the rest are reported.
- Keyboard in the Library: the arrows move between cards (the detail follows) and switch Your runs and Library; Enter or L loads, Space ticks, C compares, E exports the ticked runs, Shift+E exports all your own, U uses the run in Create, N edits the description, Delete deletes (after asking), Q swaps the focus between list and detail, B goes back to the Library from Re-play or Result, Esc leaves. A key with nothing to act on says so. Help has three new sections (Library, Import and export, Keyboard) in English and Czech.
- Cloudflare Workers AI: a fifth provider with two key slots, Cloudflare free and Cloudflare paid, each with the choices Fast (gemma-4-26b-a4b-it), Balanced (gpt-oss-120b) and Strong (qwen3.8-27b). The key is one field, ACCOUNT_ID:TOKEN. The free part is a pool of 10,000 neurons a day for all models and the whole account, reset at 00:00 UTC; the cost panel in Create estimates a run in neurons (each model carries its neuron rates), says how much of the pool it may use, and offers fewer voters or rounds, shorter answers, the lightest model for every agent, running now and continuing tomorrow, another provider, or a paid key. Settings, Keys, Cloudflare shows the pool, the neuron rates and how many typical runs fit a day. When the pool is used up the run stops with everything saved and can be continued. No web search in this version. The privacy page, Help, backups and the mock server (MOCK_CF_429=quota) cover Cloudflare.
- OpenRouter: a fourth provider with two key slots, OpenRouter free (models that cost nothing, your key needs no credits) and OpenRouter paid, each with the choices Fast, Balanced and Strong on models of its own. The free slot has limits for the whole account (20 requests a minute, 50 a day, 1000 a day after buying 10 credits, no token limits); the cost panel in Create compares a run with them in requests and offers ways out. Free models come and go: when the free slot is switched on in Create, when Create opens with it on, and with the Check models button in Settings, the app reads OpenRouter's public list (kept 30 minutes). A model that is gone blocks the agents on it until the student picks one of the free models that fit; the app proposes nothing itself, the pick is kept in Settings, and recorded runs keep their ids. If the list cannot be reached, a warning is shown and the run is allowed. The data notice says free models may train on prompts. No web search in this version. Help, the privacy pages, backups and the mock server (MOCK_OR_429=minute, day or gone) cover OpenRouter.
- Groq: a new provider with a free and a paid key slot, the models openai/gpt-oss-20b (Fast) and openai/gpt-oss-120b (Balanced and Strong, the same model), no web search in this version. Settings, Keys, Groq explains the free limits (30 requests and 8,000 tokens a minute, 1,000 requests and 200,000 tokens a day, for each model and the whole account) and the data notice before a key is saved. In Create the cost panel compares the run with those limits: it says the run fits, may be slow, may not finish today, or that one agent can never run because one call is bigger than the minute limit (Run is blocked until an offer is applied), and offers ways out (Groq for the lightest agents only, shorter answers and handoffs, run slowly, continue tomorrow, move an agent to another provider, fewer voters or rounds, a paid key). A 429 from Groq is waited out when it is short and stops the run, resumable, when it is a day limit. Backups carry the Groq keys. A shared chat-completions adapter and a local Groq mock (MOCK_GROQ_429=minute or day) are included.
- API calls: the Replay has a new tab, API calls, next to Context. For the chosen agent it shows every call to the provider in order, also the ones that failed or got no answer: what was sent (the address, the headers and the body) and what came back (the status, the headers and the body), exactly as they went over the wire. Your key is shown as (hidden), and so is anything that could identify your account. For a provider that uses another format than Anthropic (Gemini) the tab explains what the app translates. The search box of the Replay also searches the calls and opens the rows that match. The calls are kept with the run, so they are in Export run, Import, the backup and, for new recordings, the library; in an exported file the headers that identify an account are hidden and the rate-limit headers stay. A run recorded before this has no calls and says so. The log is about as big as the run itself and up to four times bigger for long runs (estimated from the recorded runs); when it would make a run larger than 2 MB, the run is saved without the log and says so. The tab follows the position of the player like Context, a row is built only when opened, a failed call says how long the app waited before trying again, seconds use the decimal comma in Czech, and a run too large to keep every body first drops the bodies of the calls that worked and keeps the failures readable. The Help section API calls explains it.
- Check models: in Settings, Keys, the button Check models next to each key asks the provider which models it offers to that key and marks every model of the app that is not offered, and the button Check all models at the top of Keys does it for every key that is loaded, one line for each. A free Gemini key is compared only with the models that have a free tier. The result is only shown: nothing is changed or saved, and a key is used for that one call only (through the new endpoint /api/models, at most 30 checks an hour from one address). The Help section API keys explains it.
- Guardrails: an agent that answers in free text can have up to 3 guardrails in the new Guardrails tab, each on what the agent receives or on what it answers. Four kinds: text that looks like a secret (known shapes of API keys, private keys, card numbers and password-like text), forbidden words (whole words, capitals ignored), too long, and a reviewing model that judges the text against a rule the student writes (it sees only the text and the rule, one more call that counts in steps, tokens and cost, and an unclear verdict blocks). A failed check can ask the agent to try again once, stop the run with the error guardrail.blocked, or only make a note; on the input only stop or note. The replay shows each check as a step with its reason, Statistics have a Guardrail hits tile, Compare has two rows, the estimate counts the extra calls, and a Retry reuses a recorded reviewer verdict. Web search results are not seen by an input guardrail. The Help section Guardrails and the Learn article Guardrails explain it.
- Format enforcement: the agents whose reply has a fixed shape (Supervisor, Evaluator, Router, Tally, Splitter, the Planner of plan-and-execute, the agents of a handoff) and the agents with an answer format ask the provider to force that shape (an Anthropic forced tool, a Gemini response schema), so a repair is rarely needed. A switch in Settings, Harness, Format turns it on (the default) or off; agents that search the web or write notes are not forced. The replay check step shows the answer that was checked, and a Retry after format.invalid asks the model again.
- Answer format: an agent that answers in free text can be asked for a fixed format, 1 to 5 named fields (text, number, yes or no, list of texts), in the new Format tab. Every answer is checked, a broken one gets one repair message, and a second failure ends the agent with the error format.invalid. The replay shows each check as a tick or a cross, Statistics has a Format repairs tile, Compare has two rows, and the Help section Answer format and the Learn article Structured output explain it (English and Czech).
- The arrows of a handoff are a rule that is enforced and shown: an agent that tries to hand over to an agent it has no arrow to (or that does not exist) is refused, is told why and may try once more; a second refusal ends the run with an error that names both agents. The replay shows each refusal as a red step of the agent, Statistics has a Refused handoffs tile, and the Help section Handoff and the Learn article Handoff explain the rule (English and Czech).
- Agents that create agents: a Supervisor or a Planner may make new workers while the run is going. The ability is off by default and is switched on in the new Creating tab of that agent, where you set the cap (1 to 4 agents, within the 8 agents of a design) and may add a short guidance and allow web search for the created agents. A created agent is a Free agent with the name and instructions its creator wrote and the creator's model; it cannot create agents itself. A Supervisor creates with the action create, a Planner lists the agents it needs with the plan and gives steps to them. A request over the cap, with a taken name or without room is refused and the creator is told why; two refusals in a row stop a Supervisor. The replay draws created agents as dashed purple cards, keeps free places in the diagram, lists the created agents in a panel under it and shows creations and refusals as steps. Statistics has a table of created agents with their calls, tokens and cost, and Compare has rows for agents created and allowed. New Help section Creating agents and the Learn article Agents that create agents (English and Czech).
- Mandatory agents are placed in the diagram when a pattern is chosen: the Combiner (parallel), the Supervisor and the Judge (debate) now appear with the other fixed agents, and an untouched diagram is replaced without the pattern-changed notice.
- The connections list of the diagram has a Show/Hide button and starts hidden.
- Help section for the Create layout setting.
- Create workspace layout: Settings, General, has a new choice, Layout of the Create page. The workspace puts the four setup parts on the left and, on the right, the agent chips, the diagram and the tabs Agents, Limits, Cost and API key, all on one screen. A bar on top shows the three status icons, the cost estimate and Run. The right side is locked until the four parts on the left are decided, and on a phone the page is one column. Both layouts use the same draft, so switching between them loses nothing. The layout applies the next time Create opens.
- Map-reduce, Plan-and-execute and self-critique: two new patterns in Create and a switch in the evaluator loop. In map-reduce a Splitter cuts the task into two to six parts, one Worker does each part at the same time and a Reducer merges the results. In plan-and-execute a Planner writes a plan of two to six steps once and an Executor carries out the steps one after another, each step seeing the earlier results. The Worker and the Executor are one box with a badge in the diagram and run once for every part or step as numbered agents (Worker 1, Worker 2). The replay lists the parts or the plan with their state, the Result tab shows how many parts or steps were done, and Compare shows a row for the number of runs. The evaluator loop has a new switch, The Writer judges its own draft: the evaluator goes away and the Writer answers a second time as its own judge. Help sections, two Learn articles and the Self-critique article are written in English and Czech.
- Comparing runs: tick two to four runs in the library and press Compare. The page shows what differs between the runs (pattern, models, web search, notebook, condensing, limits, language, provider, task), what that changed (time, cost, tokens, steps, largest context, notes, saved characters, how it ended) with the difference from the first run as neutral arrows, the results next to each other and your own verdict, which is kept in this browser (hidden when the tasks differ). A Side by side view plays up to three runs together on one clock, by time or by step. It reads the recordings, so old runs compare too. New Help section Comparing runs and the Learn article How to compare runs (English and Czech).
- Condensing, the third part of memory management: an agent can be set to Condense what this agent receives (off by default; not for a supervisor, evaluator, router or tally, which must see everything they judge). Before that agent starts, one extra call to the fast model of the same provider shortens what earlier agents passed on to at most 150 words. The task is never shortened and a text of 1500 characters or less is passed on as it is. The extra call counts as a step and its tokens are charged to the limits and the cost cap, and the estimate adds one step for each agent that condenses. The replay shows a box with the sizes before and after, the summary and the full text on demand, and a mark on the agent; Statistics counts the saved characters and the extra step. New Help text about condensing in the Memory section, and the Learn article Memory: summaries is written (English and Czech) and is no longer marked coming.
- Shared notebook, the second part of memory management: under Memory in Create you can switch on a notebook for the run (off by default) and choose for each agent None, Read, Write or Read and write (new agents start with Read and write; agents whose reply the program reads as a decision, such as a supervisor, evaluator, router, tally or any agent in a handoff, can only read). An agent that may write ends its answer with a note; the program takes the note out of the text that goes on and adds it to the notebook, and an agent that may read gets the notes so far at the end of its input. Notes are cut at 600 characters and an agent reads at most the last 6000 characters. No extra model calls and nothing is kept between runs. The replay shows the notebook as a panel with the author of each note and marks on the agents (wrote, read), and the Context tab counts the notebook as a part of the input. The design records the switch and the choice of each agent, so runs with and without the notebook can be compared later. New Help section Memory with a detailed explanation of the notebook and of each choice; the Learn article Memory: shared scratchpad is written (English and Czech) and is no longer marked coming.
- Context view, the first part of memory management: a Context tab in the replay shows, for each model call of the chosen agent, the exact input tokens and what the call was made of (instructions, the task, what other agents passed on, its own earlier messages, as shares of characters). The Statistics tab has a Largest context tile and a Context per call figure. It reads the events already recorded, so it also works on old recordings. New Help sections Context and Context per call; the Learn article on the context window points to them (English and Czech).
- Voting: an eighth pattern in Create. Three to five voters answer the same task alone, and one tally agent (added for you) reads all the answers and names the answer most of them agree on, which voters agree and what differs, in JSON that the program reads. The tally answer is the result. The replay shows who agreed (the voter that differs is dashed and dimmed) and the count; the Result tab shows a notice (majority, no majority, or stopped by a limit) and an Agree tile. New Help section Voting with its own ? button in Create, and the Learn article Voting (English and Czech).
- Router: a seventh pattern in Create. One router agent (added for you) reads the task and chooses one of two to six specialists, once; the specialist gets only the task and its answer is the result. The router answers in JSON with the id and a reason, and the program reads it. The replay shows the choice, the reason and the specialists not called; the Result tab shows a notice and a Routed to tile. A run ends answered, stopped by a limit (no result) or failed. New Help section Router with its own ? button in Create, and the Learn article Router (English and Czech).
- Handoff: a sixth pattern in Create. Agents are joined by arrows that mean may hand over to, and one agent is marked as the start. The start agent works on the task and then hands control to an agent it has an arrow to, with a note, or finishes. The next agent gets the task and the note and nothing else. Arrows may run both ways. A run ends finished, stopped by a limit (the result is the last note, nobody finished the task) or failed. The replay shows who holds control and the path, the Result tab shows a notice, a Handoffs tile and the path. Help has a new section Handoff with all the ways of passing information at a handoff and why Agent Atlas uses the note plus the task, with its own ? button in Create. The Learn article Handoff is rewritten (English and Czech) and is no longer marked coming.
- Evaluator loop: a fifth pattern in Create. A writer drafts, an evaluator judges the draft against criteria that you write, and the writer revises, for 1 to 4 rounds. The evaluator accepts or sends feedback, and the program reads that verdict. A loop ends accepted, not accepted (the rounds ran out, the last draft is the result and is marked), or stopped by a limit. The replay shows the round and a notice at the end, the Result tab shows the notice and a Loop tile, and Create warns when no criteria are written. The Learn article Evaluator loop is written (English and Czech) and is no longer marked coming.
